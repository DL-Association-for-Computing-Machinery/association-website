# 测试、发布与回滚检查清单

## PR 合并前

- [ ] 关联 GitHub Issue，验收标准逐项完成。
- [ ] 公开内容已脱敏，来源、授权、审核主体和结论已记录；AI 自审适用。
- [ ] 构建能在没有飞书令牌的环境中执行。
- [ ] 页面标题层级、跳过导航、焦点状态、键盘操作和图片替代文本已检查。
- [ ] 站内链接、外部报名链接和图片资源没有明显失效项。
- [ ] 移动端和桌面端至少各完成一次静态预览。

## 预发布

前置条件：部署平台、预览入口与所需权限已验证；截至本轮尚未执行。应用构建命令和 CI 由 #3、#4、#6、#7 落实。当前纯文档提交只运行差异、相对链接、素材格式/尺寸/摘要与内容规则检查，不把它们报告为网站构建通过。

1. 从合并后的 `main` 构建静态产物。
2. 检查首页、活动、成果、知识和加入入口。
3. 抽查公开内容来源和个人信息脱敏。
4. 记录构建版本、发布地址、检查人和已知问题。
5. 发布后打开首页、一个活动详情、一个成果条目和加入入口完成 smoke test。

## 回滚

- 内容错误：回退到上一份审核通过的内容提交并重新发布。
- 构建或页面错误：回滚到上一个可用 Git 提交，不修改飞书原始资料。
- 外部报名链接失效：先替换或下线入口，保留问题记录，再恢复公开入口。
- 飞书读取失败：继续使用仓库内上一版公开内容，不让线上页面等待飞书服务。

## 记录位置

发布结果写入对应 GitHub PR 和“官网项目索引”飞书文档；事故或回滚补充到相关 Issue，不只留在群聊里。
