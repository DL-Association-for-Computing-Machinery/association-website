## InkWords：知识内容工作台参考

InkWords 是一个本地知识训练平台，核心闭环是“资料摄入 → 知识整理 → Obsidian 沉淀 → 知识复习 → 输出为博客/PDF/Obsidian”。仓库目前采用 React + Vite 前端、Go 多服务后端、PostgreSQL、RabbitMQ、Redis 和 Docker Compose。

对协会官网最有用的部分不是直接复用整套系统，而是内容治理思路：

- 支持 Git 仓库、技术文档、PDF、DOCX、Markdown、TXT 和 ZIP 的资料摄入。
- 使用 `sources/`、`concepts/`、`entities/` 和索引页组织长期知识。
- 通过异步任务、导出和版本化流程处理长内容。
- 将项目目标、知识库引用、草稿和产出回编到知识库，形成可追踪的项目闭环。
- 仓库中的 `AGENTS.md` 对来源、证据、权限边界、测试和发布质量有明确约束，可作为协会内容工作流写法的参考。

官网阶段只复用“公开内容字段、来源记录、审核状态、链接/图片巡检、版本记录”这些轻量原则，不引入 InkWords 的多服务、LLM 生成、复习系统或 Obsidian 桥接。

## load-balanced-online-oj：OJ 阶段参考实现

该项目是面向算法竞赛的 C++ 在线评测系统，包含：

- OJ 主服务器：题目、提交、评测任务调度和结果汇总。
- 编译服务器池：多个编译/运行实例，通过主服务器按负载分发任务。
- MySQL：用户、题目、提交、竞赛等数据。
- 用户认证、管理员后台、题单、竞赛爬虫、讨论和数据统计。
- Linux Namespace、权限降级和资源限制等评测沙箱安全措施。

它可以作为官网需求中 RQ-02 OJ 平台的候选基础或技术调研样本。它不能直接作为宣传官网的前端模块嵌入，因为判题执行、沙箱、资源限制、题库管理、用户体系和运维隔离都属于独立平台边界。

## 对官网阶段规划的影响

1. 官网 MVP：只提供 OJ 入口、训练说明、学习资源和外部系统链接，不承载判题执行。
2. OJ 阶段：先完成安全评估、部署拓扑、题库/用户迁移方案、评测资源隔离和故障恢复设计，再决定自建或改造该项目。
3. 知识内容阶段：借鉴 InkWords 的来源、审核、版本和巡检约定，把飞书知识库内容转成官网公开内容。
4. 代码复用边界：保留原项目链接和研究结论；没有经过许可证、依赖、安全和运维评估前，不复制实现代码或把两个项目合并进官网仓库。

## 建议的仓库组织

组织 `DL-Association-for-Computing-Machinery` 当前可作为协会项目归属。官网仓库单独维护；未来可以将 OJ、内容同步脚本和设计资源拆成独立仓库，通过 README 和版本发布互相链接。
